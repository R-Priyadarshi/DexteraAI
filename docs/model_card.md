# Model Card: GestureTransformer

## Model details

| Property | Value |
|---|---|
| Name | GestureTransformer |
| Architecture | Transformer encoder (pre-norm) with a prepended CLS token |
| Parameters | 551,771 for a 26-class head |
| Size | 2.1 MB fp32; smaller after `--quantize` |
| Input | `(batch, seq_len, 86)` landmark features + `(batch, seq_len)` padding mask |
| Output | `logits (batch, num_classes)` and an auxiliary `confidence (batch,)` |
| Framework | PyTorch, exported to ONNX (opset 17) |
| License | MIT (code). Training data licensing is separate: see [DATASET_LICENSES.md](DATASET_LICENSES.md) |

A smaller `StaticGestureClassifier` MLP (59,419 params, 0.23 MB) is available in
`core/temporal/static_model.py` as a single-frame baseline.

For sign language beyond fingerspelling, `core/landmarks/holistic_features.py`
produces a 208-dim body-relative vector (both hands plus upper-body pose, scaled
by shoulder span). The same `GestureTransformer` accepts it by setting
`input_dim=208` and a longer `max_seq_len`. No word-level model is trained: the
standard corpus (WLASL) is research-licensed. See DATASET_LICENSES.md.

## Architecture

```
Input (B, S, 86)
  → Linear 86→128 + LayerNorm + GELU + Dropout
  → Prepend CLS token
  → Sinusoidal positional encoding
  → 4 × TransformerEncoderLayer (d_model=128, heads=4, ff=256, pre-norm, GELU)
  → CLS token output
  → Classifier head 128 → 64 → num_classes
  → Confidence head 128 → 1 (sigmoid)
```

The 86-dim input is not pixels. Per frame it is: 21 normalized 3D landmark
coordinates (63), fingertip-to-wrist distances (5), fingertip pairwise distances
(10), per-finger curl ratios (5), and the palm normal (3).

## Intended use

- **Primary**: recognizing a held hand gesture from a webcam, on-device.
- **Secondary**: ASL fingerspelling recognition; accessibility input; AR/VR input.
- **Out of scope**: continuous sign-language translation; medical, automotive, or
  any safety-critical use; identifying individuals.

## Training data

Two separately-trained bundles, each shipping its own `labels.json`:

| Bundle | Classes | Landmark samples | Source |
|---|---|---|---|
| `models/hagrid` | 18 general gestures | 65,802 | HaGRID (512px classification subset) |
| `models/asl_alphabet` | 26 ASL letters | 8,638 | ASL alphabet dataset |

Sample counts are post-detection: images where MediaPipe found no hand are dropped
(HaGRID ~70-94% detection depending on shard, ASL ~79%). Only landmarks are stored;
source images are never persisted.

Augmentation during training: rotation, scale, translation, and Gaussian noise in
landmark space, applied per frame so a held gesture varies slightly across the
window, mimicking natural hand tremor.

## Evaluation

Metrics are computed on a held-out test split that is never trained or validated
on (`--test-split`, default 15%). Splits are random, **not** subject-disjoint,
because these datasets do not expose subject IDs. Real-world accuracy on unseen
people will be lower than the reported numbers.

| Bundle | Classes | Test accuracy | Macro F1 | Top-3 | Test samples |
|---|---|---|---|---|---|
| `models/hagrid` | 18 | 0.9814 | 0.9804 | 0.9938 | 9,870 |
| `models/asl_alphabet` | 26 | 0.9382 | 0.9355 | 0.9762 | 1,295 |

Confidence calibration (general-gesture bundle): temperature 0.736, expected
calibration error 0.089 to 0.017, rejection threshold 0.30 holding 97.9%
accuracy at 100% coverage.

Full reports are in `reports/eval_<dataset>.json`, regenerated by:

```bash
python dextera.py train --dataset data/sequences/<name> --epochs 80 --export models/<name>
```

## Latency

Measured on CPU (see README for full table). The classifier is ~0.1 ms per window
and is not the bottleneck; MediaPipe hand detection (~47 ms p50 on 720p CPU)
dominates end-to-end latency.

## Limitations

- Needs reasonable lighting for MediaPipe to find the hand at all. Detection
  failure, not misclassification, is the most common failure mode.
- Degrades under heavy occlusion and at extreme hand angles.
- Trained on one hand at a time.
- Closed-set: without the confidence threshold from
  `training/evaluation/calibrate_confidence.py`, an out-of-vocabulary gesture will
  still be assigned one of the trained labels.
- Random (not subject-disjoint) splits mean reported accuracy is optimistic
  relative to new users.
- Not validated across skin tones, hand sizes, or limb differences. The training
  corpora's demographic composition has not been audited.

## Ethical considerations

- **Privacy**: landmark-only processing, on-device. No images stored or transmitted.
- **Bias**: unaudited. Anyone deploying this should evaluate across diverse hand
  shapes, skin tones, and motor abilities before relying on it.
- **Accessibility**: per-user calibration (`core/calibration/`) and in-browser
  custom gestures exist so users whose hands the base model handles poorly can
  teach it their own.

## Environmental impact

Training either bundle takes minutes on a single consumer GPU. Inference is CPU-
capable and needs no cloud infrastructure.
